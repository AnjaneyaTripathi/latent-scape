# Latentscape

Latentscape is a static, concept-first map of NeurIPS and ICML research. It runs entirely on GitHub Pages: search, embeddings, paper metadata, summaries, and graphs are generated before deployment. The browser makes no research, LLM, or embedding API calls and never hosts paper PDFs.

This repository currently ships an auditable **500-paper MVP preview**, not a complete corpus: 316 NeurIPS papers and 184 ICML papers organized into 13 topics. It includes 200 Astra-authored summaries and 50 citation matches (10%). The final artifact is 86.36 MB across 245 files. See the [build report](docs/build-report.json) and [data sources](docs/data-sources.md) for the measured output and coverage limits.

## Run the MVP

Requires Python 3.12+, [uv](https://docs.astral.sh/uv/), and Node 22+.

```sh
uv sync
uv run latentscape ingest-sample
uv run latentscape repair-sample
uv run latentscape replace-missing
uv run latentscape enrich --corpus sample
uv run latentscape merge-enrichment --corpus sample
python3 pipeline/scripts/stage_embedding_model.py
uv run latentscape embed --corpus sample
uv run latentscape cluster --corpus sample
uv run latentscape similarity --corpus sample
uv run latentscape summary-batch --corpus sample --limit 200
```

`summary-batch` writes the checkpointed 200-paper review input and its direct API-cost estimate. The one-time review sample is generated by the Astra agent and imported from its checked-in mapping; it needs no API key. The estimate does not claim to account for agent model usage:

```sh
uv run latentscape import-summaries --corpus sample --summary-file data/generated/summaries-astra-sample.json
uv run latentscape import-topics --corpus sample
uv run latentscape glossary --corpus sample
uv run latentscape export --corpus sample
python3 scripts/write-summary-review.py
cd site && npm ci && npm run build
cd ..
python3 scripts/write-artifact-report.py site/dist
python3 scripts/validate-artifacts.py site/dist
```

Copy `config.example.toml` to `config.toml` only to change local build settings. It is ignored by Git. Do not commit API keys; the supplied Astra review path uses no paid API.

The ingest cache makes source collection resumable. `data/generated/papers-sample-snapshot.json` is the reviewed MVP selection; `ingest-sample` restores it on a clean clone rather than selecting a new 500. Use `ingest-sample --new-sample` only when deliberately replacing that reviewed selection, then regenerate embeddings, clusters, summaries, topic prose, and static output. The checked-in site can be rebuilt deterministically with `npm ci && npm run build`; rerunning pipeline stages instead uses the checked-in Astra summary and topic imports for this reviewed sample. The `all-sample` command only regenerates mechanical sample artifacts; it does not ingest, author, or import the curated Astra content. The full-corpus command exists as `uv run latentscape ingest-full`, but must not be represented as complete until its coverage audit has no intended source gaps and the later embedding/vector stages have run. The final preview samples NeurIPS 1988–2025 and ICML 2017–2026; the 1987 sample candidate was replaced because its official record has no usable abstract. The source audit keeps that year visible rather than concealing it. The 2026 NeurIPS index is explicitly `not_published`; earlier ICML years remain audit gaps.

## Develop and verify the site

```sh
cd site
npm ci
npm run dev
```

After a production build, run the artifact checks above. They enforce GitHub Pages' decimal 100 MB file and 1 GB site limits, reject PDFs and remote generated assets, and require the local MiniLM ONNX/WASM runtime plus data schema and report. They also verify every paper/topic/vector reference, vector shape, duplicate IDs, citation provenance, and summary counts. For a review gate that requires a specific number, add `--expected-summaries 200` to the validator command.

For a browser smoke test of the built artifact, use a local Playwright installation:

```sh
LATENTSCAPE_PLAYWRIGHT_ROOT=/path/to/node_modules node scripts/browser-smoke.mjs site/dist
```

It checks same-origin runtime requests, offline-after-load search, detail routing, themes, mobile width, and a missing route.

## Data and deployment

`pipeline/` owns offline collection, enrichment, clustering, summaries, and export. `site/` is the Vite static application. Browser data begins at `site/public/data/manifest.json`; its format is defined in [the data contract](pipeline/CONTRACT.md).

The Pages workflow only builds committed static inputs. It never runs pipeline collection, calls a research/LLM API, or downloads a model. Before enabling the workflow for a repository, set **Settings → Pages → Build and deployment → GitHub Actions**. The deployment artifact is generated and validated first; publishing remains a separate repository action.

The generated `data/report.json` records paper/topic counts, coverage, and final site bytes. See [architecture](docs/architecture.md) and [summary provenance](docs/summary-provenance.md) for the static/runtime and AI-summary boundaries.

After the 200 summaries are imported, `scripts/write-summary-review.py` emits `site/public/summary-review.html`: a self-contained, local review artifact with every TLDR and detailed summary, original-paper links, and Astra provenance. It is copied to `site/dist/summary-review.html` by the production build.

## Model provenance

Query embeddings use the browser-compatible `Xenova/all-MiniLM-L6-v2` model. Its [model card](https://huggingface.co/Xenova/all-MiniLM-L6-v2) declares Apache-2.0. The vendored snapshot is revision `751bff37182d3f1213fa05d7196b954e230abad9`; [ASSET-AUDIT.json](site/public/models/Xenova/all-MiniLM-L6-v2/ASSET-AUDIT.json) pins SHA-256 hashes for the tokenizer and quantized ONNX model. `pipeline/scripts/stage_embedding_model.py` verifies those hashes while staging the same assets at `pipeline/.cache/models/Xenova/all-MiniLM-L6-v2` for the offline embedding stage.

The embedding model setting is intentionally pinned to this browser-shipped model. Changing it is rejected until matching local model assets and browser runtime support are added together.
